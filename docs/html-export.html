Designing for HTML Export

How to build a design so that "Export as HTML" produces clean, readable HTML and CSS instead of a pile of absolutely positioned boxes and images.

The exporter never drops a layer: anything it can't describe with CSS is rendered to a PNG and placed where it was drawn. So every export looks right. Whether it's also good HTML (real elements, real text, flex rows and columns, few images) depends on how the design is built. This page lists the rules the exporter follows (src/html_export/, src/css_rules.rs) and how to design for them.

Running an export

  • File > Export Selection as HTML… exports the one selected layer, using the layout mode last chosen in the Export dialog.
  • Export dialog (⌘E, or File > Export Selection…): pick HTML layout (Flexbox or Absolute), then Export as HTML…. Format and scale only apply to PNG export, not here.

You pick a folder, and the export goes into a subfolder named after the layer: 

<layer name>/
  index.html     one element per layer, nested like the layer tree
  style.css      one commented rule per layer (/* layer name */ .layer-N { ... })
  images/        PNGs for image layers and rasterized layers
  fonts/         the bundled font files the text uses, with @font-face rules

Export an artboard: it becomes the page box, its background becomes the page background, and the output is sized to it. The exported layer must be visible (a hidden one is an error). Hidden children are left out entirely.

Choosing a layout mode

ModeWhat you getUse it for
Flexbox (default) Rows, columns and grids inferred from where things sit, with gap, align-items and padding. Elements that can't flow stay absolutely positioned on top. A starting point for a real page: text can grow and push content down.
Absolute Every element at its exact left/top, nested like the layer tree. A pixel-exact mockup, or a design with lots of overlap.

The rest of this page is mostly about getting good Flexbox output.

What becomes CSS, what becomes an image

LayerExported as
Artboard, GroupA <div> containing its children — unless a child is a mask, then the whole container becomes one PNG
Rectangle, OvalA styled <div> (background, border, border-radius, box-shadow) — if the fill is solid or a gradient
Line, ArrowA zero-height <div> with a top border, rotated. Arrowheads aren't drawn.
TextA <div> with real, selectable text; rich-text runs become <span>s
ImageAn <img> of the original image bytes — unless it has a color adjustment, then a rendered PNG
Star, Polygon, Path, Compound Path, Boolean GroupAlways a PNG
Text on a pathAlways a PNG
Any shape with a Noise, Halftone or Pattern fillAlways a PNG

PNGs are rendered at 2× (sharp on high-density screens) and include the layer's drop shadows and opacity. They're placed by their exact bounds and never join a flex row or column.

To keep things as real HTML:

  • Draw buttons, cards, chips and panels as rectangles (per-corner radius is fine), not as paths or boolean shapes.
  • Use solid or gradient fills for anything that should stay CSS. Save noise, halftone and pattern fills for decorative pieces you're happy to ship as images.
  • Use masks only where an image is acceptable: one mask turns its whole group into a single PNG, text included. Keep the masked part in its own small group, separate from the content around it.
  • Make icons and illustrations their own groups or path layers, so they rasterize alone and don't drag neighbouring elements into the image.

Layout: how Flexbox mode reads your design

For each artboard and group, the exporter looks at its visible children's bounding boxes and cuts them apart along straight lines of empty space ("XY-cut", html_export/layout_inference.rs): first top-to-bottom into a column, otherwise left-to-right into a row, then cuts each part again. The result is nested flex rows and columns, emitted in visual order (top-to-bottom, left-to-right), with the original layer order kept through z-index.

Leave clear gutters

Two elements only end up in different rows (or columns) if a full-width (or full-height) strip of empty space separates them. Edges that touch count as separated; any overlap doesn't. Line things up on a grid, keep sections apart, and avoid an element that pokes into the next row's band.

Overlap costs you flow

When elements overlap so that no cut can separate them, the largest one is taken out of the flow and absolutely positioned, and the cut is retried on the rest. That's exactly right for a backdrop rectangle behind some content — the content still flows. But heavy overlap (badges on corners, stacked decorations) leaves many elements absolutely positioned. Group the overlapping pieces together so the overlap stays inside one group.

Use groups as containers

Every group is a container whose own children are laid out the same way, so groups decide the structure of the HTML. Group what belongs together — a card's background, image, title and text; a nav bar's links; a form's fields — and the HTML follows that structure.

Be consistent with spacing and alignment

  • Gaps between items in a row or column that are within 3 units of each other become one averaged gap. Uneven gaps become one margin per item — correct, but noisier.
  • Items that share a left/top edge, a center, or a right/bottom edge (again within 3 units) become one align-items. Otherwise each item gets its own offset margin.
  • Snapping moves elements by at most 3 units. Use the alignment and distribute tools, or a grid, so the spacing is exact.

Grids

A column of rows becomes display: grid when it's at least 2×2, every row has the same number of cells, each column starts at the same x in every row, cells in a row share a top edge, and the space between columns is even (all within 3 units). Card galleries and icon grids built with the grid tool usually qualify. A grid with one card missing in the last row doesn't — it falls back to flex rows.

What always stays absolutely positioned

  • Rotated layers, lines and arrows, and anything rasterized.
  • Anything that sticks out past its container's top or left edge (flex padding can't be negative). Keep children inside their artboard or group.

Text

  • Resize mode matters. In Flexbox mode, Auto and Auto Height text gets min-height, so if the browser's text is longer it pushes the following elements down instead of overlapping them. Fixed text keeps a fixed height. Auto (single-line) text never wraps (white-space: pre); the others wrap at the box width.
  • Prefer the bundled fonts (Ubuntu, Hack, Merriweather, Poppins, Caveat): their files are shipped in fonts/, so the browser draws the same glyphs as the canvas. System fonts are referenced by name only and fall back to a generic family on a machine that doesn't have them.
  • Only regular and bold weights ship. Italic uses the browser's slanted version.
  • Text color is always flat: a gradient fill on text exports as one color, the same as what the canvas draws.
  • Carried over: size, line height, letter spacing, alignment, bold/italic, underline/strikethrough, case transform, text stroke, drop shadows (without spread). Not carried over: vertical alignment, paragraph spacing, list bullets or numbering, and inner shadows on text. Avoid relying on them for a design meant for HTML.
  • Keep text as text: don't convert it to outlines, and don't put it on a path or inside a masked group, or it becomes part of an image.

Styling details

  • Fill opacity and stroke opacity are folded into the color's alpha; layer opacity becomes opacity.
  • Strokes become CSS borders. A gradient stroke uses border-image, which browsers draw square even on rounded corners — use solid strokes on rounded shapes.
  • Drop and inner shadows on shapes become one box-shadow, following the box (including its radius).

Names

Layer names show up in the output: the exported layer's name is the folder name and the page <title>, every CSS rule is headed by a /* layer name */ comment, and images use it as their alt text. Name layers for what they are ("Hero image", "Sign up button"), not "Rectangle 12".

Checklist

  • Export an artboard, with everything inside it.
  • Group related elements; keep overlap inside groups.
  • Leave clean gutters between rows and columns; use exact, repeated spacing.
  • Rectangles and ovals with solid or gradient fills for UI; rasterize only on purpose.
  • No masks around content you want as HTML.
  • Bundled fonts, Auto Height text for paragraphs, no vertical-align/list/paragraph-spacing reliance.
  • Meaningful layer names.
  • Open index.html and check that the elements you expected are flowing (no position: absolute in their rule) and that images/ holds only what you meant to rasterize.
