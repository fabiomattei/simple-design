Getting Started

Build, run, and test the app from a fresh checkout.

Requirements

  • A recent stable Rust toolchain (edition 2024) — install via rustup
  • macOS or Linux — system_fonts.rs discovers OS-installed fonts on these platforms via fontdb
  • No web/webview runtime, no Node — this is a native eframe window

Commands

CommandWhat it does
cargo buildCompile the app
cargo checkType-check only — fast, prefer this while iterating
cargo runLaunch the app — opens a native window, it's a GUI app, not a CLI
cargo testRun all tests
cargo test <test_name>Run one test, e.g. cargo test renders_filled_rect_at_correct_size_and_color

Tests currently live alongside src/export.rs and src/io.rs (#[cfg(test)] mod tests), primarily covering the PNG renderer's pixel output and file round-trips. There is no separate lint/format CI — cargo check emitting no warnings is the bar to clear before considering a change done.

First run

git clone <repo-url>
cd simple-design
cargo run

A blank document opens with one page. Use the toolbar or keyboard shortcuts (see Tools & Features) to start drawing — R for a rectangle, O for an oval, T for text, and so on. ⌘S saves a .sdesign file (see File Format).

Working on this codebase

This project pins egui/eframe 0.36, which is bleeding-edge enough that its APIs differ from most existing documentation and training data — notably the App::ui signature, panel construction (egui::Panel::top/bottom/left/right instead of separate TopBottomPanel/SidePanel types), and menu bars (egui::MenuBar::new().ui(...)). Before assuming an API from memory, check ~/.cargo/registry/src/*/egui-0.36.0/src/ directly. See the repository's CLAUDE.md for the full list of gotchas.

When adding a new shape or tool, the touch points (in order) are: tools.rs, model/layer.rs, canvas.rs, export.rs, ui/inspector.rs, and ui/layers_panel.rs — see Architecture for what each one needs.
