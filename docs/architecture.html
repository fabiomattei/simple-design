Architecture

Module map and the conventions that hold the codebase together.

Module map

Canvas & rendering

ModuleResponsibility
canvas.rsThe interactive canvas: coordinate transforms, hit-testing, drawing, and all drag/click gesture handling. The largest and most subtle file (~7,000 lines) — see the drag state machine below.
export.rsRenders a single Layer subtree to a tiny-skia Pixmap and saves PNG. A completely separate implementation from the canvas renderer, not shared code — any new LayerKind/Paint variant needs a matching implementation here too.
shapes.rsPure geometry generators (ellipse/star/polygon points, rounded corners, rotation) shared by the canvas renderer, PNG exporter, and boolean-op flattening — no egui painter / tiny-skia dependency.
masking.rsThe one masking algorithm both canvas.rs and export.rs share, so they can never disagree about what a mask looks like. Operates purely on tiny_skia::Pixmap/Layer, no egui dependency.
shadow.rsDrop ("outer") and inner shadow rendering (Style::shadows/inner_shadows). Same shared-algorithm-over-Pixmap shape as masking.rs; blur is a 3-pass box blur approximating Gaussian.
noise_fill.rs / halftone_fill.rsProcedural fill samplers backing Paint::Noise/Paint::Halftone. Each exposes one deterministic sample(..) function called independently by canvas.rs and export.rs, so the same seed/params rasterize identically at any resolution with no shared texture.
text_layout.rs / text_outline.rsCanvas-side text layout (egui Galleys, plain and rich) and glyph-to-vector-outline conversion, respectively.
fonts.rs / system_fonts.rsBundled and OS-discovered font registration; the single source of truth mapping any TextFont to raw bytes. See Text & Fonts.

Data model

The document schema is a tree, all pure serde-serializable data with no UI-framework dependency beyond plain egui geometry/color types: 

Document
├─ name: String, active_page: usize
├─ text_styles: Vec<TextStyle>     (shared paragraph-level text styles)
├─ layer_styles: Vec<LayerStyle>   (shared fill/stroke/shadow styles)
├─ palette: Palette                (color-swatch library)
└─ pages: Vec<Page>
   └─ Page { id, name, guides: Vec<Guide>, layers: Vec<Layer> }
      └─ Layer (recursive; children only for Artboard/Group/BooleanGroup)

Layer is the schema's atom — every shape, container, text box, and image on the canvas is one. Besides id/name/kind, every layer carries:

  • frame: Frame { pos, size, rotation } — parent-relative position/size (see Coordinate system convention below); rotation only ever nonzero on a leaf shape.
  • style: Style — fill: Option<Paint>, stroke: Option<Stroke>, independent fill_opacity/ stroke_opacity, and stacked shadows/inner_shadows.
  • visible, locked, and opacity (multiplies into descendants' effective opacity when drawn).
  • is_mask/ignore_mask — Sketch-style "use as mask"; see masking.rs.
  • bool_op: BoolOp — meaningful only as a direct child of a BooleanGroup, ignored everywhere else.
  • style_id: Option<Uuid> — links to a Document::layer_styles entry; a direct style edit leaves the link in place, only "Detach" clears it.

LayerKind has thirteen variants — Artboard/Group/ BooleanGroup (the only three with children: Vec<Layer>), Rectangle, Oval, Line, Star, Polygon, Arrow, Path, CompoundPath, Text, and Image. See File Format for the full field-by-field table and JSON shape of each.

Paint — a fill or stroke color source — is #[serde(untagged)] so a plain Solid color round-trips as a bare Color32, the shape older save files already used:

  • Solid(Color32)
  • Gradient(Gradient) — Linear/Radial, stops: Vec<GradientStop>, from/to normalized 0.0..=1.0 points in the shape's unrotated bounding box.
  • Noise(NoiseFill) — procedural grain (fill-only); see noise_fill.rs.
  • Halftone(HalftoneFill) — procedural dot grid (fill-only); see halftone_fill.rs.
  • Pattern(PatternFill) — tiled bitmap (fill-only); PNG bytes + tile_width.

Two shared style libraries live on Document, each linked from a layer by a style_id that a direct edit leaves untouched:

  • TextStyle (Document::text_styles) — every per-layer Text style field except content/geometry, linked via LayerKind::Text::style_id. Applying one to a layer with rich per-run formatting resets that layer back to uniform styling.
  • LayerStyle (Document::layer_styles) — every Style field (fill/stroke/opacities/shadows) plus id/name, linked via Layer::style_id.

Most schema growth is purely additive — a new field gets #[serde(default)] (opacity, rotation, runs, is_mask, …) so old documents just load with that default. CornerRadii is the one exception, and the reference pattern for any future non-additive change: it has a hand-written Deserialize accepting either a bare number (pre-per-corner-rounding files, applied uniformly to all four corners) or the current four-field object.

Coordinate system convention

A Layer.frame.pos is relative to its parent (the page, or an enclosing Artboard/Group), not absolute. Two things follow everywhere shapes are drawn, hit-tested, or exported:

  • To get a layer's position in page/doc-space, add the accumulated offset of its ancestors — Page::absolute_offset(id) computes exactly that by walking down from the page root.
  • Recursion into children always threads offset + layer.frame.pos.to_vec2() as the new base offset (canvas.rs::draw_layer, export.rs::draw_layer, hit_test_layers). Any new recursive traversal over the layer tree must follow the same accumulation, or nested shapes will render/hit-test in the wrong place.

Separately, Frame (model/layer.rs) stores raw pos + size, where size can be negative — this preserves drag direction for the Line/Arrow shapes (a line dragged bottom-right→top-left renders correctly). Use frame.bounds() to get a normalized, axis-aligned egui::Rect for anything that isn't direction-sensitive (hit-testing, fill/stroke rendering, resize-handle placement) — don't assume frame.pos is the visual top-left. When rotation is involved, use frame.rotated_bounds() instead, which gives the shape's actual on-screen footprint.

Drag state machine (canvas.rs)

All mouse interaction on the canvas — panning, shape creation, marquee/rubber-band select, single moves, group moves, single-layer resize, group bounding-box resize, and rotation — is modeled as one DragState enum, set on drag_started(), advanced on dragged(), and resolved on drag_stopped(). Adding a new canvas interaction means adding a new DragState variant rather than introducing separate ad hoc mutable fields.

Representative variants:

  • PanningView, CreatingShape
  • Marquee — rubber-band selection over empty canvas, tracking additive/contained_only/ignore_groups/invert modifier state captured at drag start
  • MarqueePoints — the same idea for selecting points on a single active Path
  • MovingSelection
  • ResizingLine — special-cased single-line endpoint drag that preserves exact drag direction, which a bounds-based scale transform would lose
  • ResizingGroup — captures every selected layer's absolute bounds before the drag begins, then applies one scale+translate transform per frame; covers single non-line resize and multi-selection group resize alike
Two resize code paths intentionally exist side by side: ResizingLine (exact endpoint/direction) and ResizingGroup (bounding-box proportional scale, used for everything else). A mixed multi-select that includes a Line falls back to the bounding-box path and loses exact line-direction fidelity — a known, accepted tradeoff.

Undo model (history.rs)

History wraps the live Document plus past/future stacks of full Document clones — there is no command/diff pattern. The convention used everywhere: call history.snapshot() before mutating (it pushes the current state to past), then mutate via history.mutate(). For a continuous gesture (a drag), only snapshot on the frame the gesture starts — see ui/inspector.rs's should_snapshot() helper for the pattern.

Known simplifications

These are accepted tradeoffs, not open bugs — see ROADMAP.md for the full gap list vs. Sketch:

  • Rotation is only ever nonzero on a leaf shape layer. A Group/Artboard/BooleanGroup's own rotation is always 0.0; rotating one bakes the angle into each descendant's own frame instead.
  • Text supports the Sketch-style single-style-per-layer typography properties and per-character rich text, but no italic/oblique face selection (italic is always the faux-shear trick), no text-on-a-path, and no OpenType features.
  • Marquee-select only matches top-level layers on the active page by default; shift-click reaches descendants directly, and holding ⌘ while marquee-dragging descends into groups/artboards.
  • Snap candidates (other layers' edges/centers, plus guides) are built from top-level layers only, same simplification as marquee-select.
  • show_rulers/show_grid/snap_enabled are runtime View-menu toggles, not persisted with the document — only guides themselves are (Page.guides).

Adding a new shape/tool

Touch points, in order:

  1. tools.rs — add the Tool variant and its keyboard shortcut
  2. model/layer.rs — add the LayerKind variant
  3. canvas.rs — new_layer_for_tool, draw_layer (hit_test_layers already handles bounds generically via frame.bounds())
  4. export.rs — draw_layer; PNG rendering is a separate implementation from the canvas one, not shared
  5. ui/inspector.rs — property editing UI
  6. ui/layers_panel.rs's icon_for — label only
