Packaging

Two ways to get a system-integrated build on Linux: a plain .desktop entry, or a sandboxed Flatpak.

cargo run / a bare release binary never gets a dock, alt-tab, or app-grid icon on GNOME under Wayland. Wayland only resolves a window's icon through a .desktop file matched by the window's app_id — there's no other mechanism for a toolkit to hand the compositor an icon directly. src/main.rs sets with_app_id("simple-design") for exactly this reason; both packaging methods below rely on it matching a .desktop file's StartupWMClass.

Desktop entry (unsandboxed)

The plain option: install a .desktop file pointing at the locally built binary, no sandboxing involved. Files live in packaging/linux/.

FilePurpose
simple-design.desktopTemplate with __EXEC_PATH__ / __ICON_PATH__ placeholders
install.shsed-substitutes the placeholders with absolute paths into ~/.local/share/applications/
cargo build --release
./packaging/linux/install.sh

This resolves ${repo}/target/release/simple-design and ${repo}/assets/icon.png to absolute paths at install time, so the entry only works from this checkout — rebuilding in place is enough to pick up updates, no reinstall needed. If the icon still doesn't show up after installing, log out/in or restart GNOME Shell (Alt+F2, r) — the shell caches app icons.

Flatpak (sandboxed)

The distributable option: a real Flatpak app, io.github.fabiomattei.simple-design, built entirely from this repo. Files live in packaging/flatpak/.

FilePurpose
io.github.fabiomattei.simple-design.ymlThe build manifest
io.github.fabiomattei.simple-design.desktopFlatpak-specific desktop entry (Exec=simple-design, Icon=<app-id>)
io.github.fabiomattei.simple-design.metainfo.xmlAppStream metadata (license, summary, releases)
icon.png256×256 square version of assets/icon.png — Flatpak's exporter rejects non-square icons, and the source asset is 333×346

Build setup

Runtime: org.freedesktop.Platform / org.freedesktop.Sdk 25.08, plus the rust-stable SDK extension (installed once, system-wide):

flatpak install flathub org.freedesktop.Sdk.Extension.rust-stable//25.08

Build & install

cd packaging/flatpak
flatpak-builder --force-clean --user --install builddir \
  io.github.fabiomattei.simple-design.yml

Run it with:

flatpak run io.github.fabiomattei.simple-design

Sandbox permissions

The app requests the minimum needed to draw a window and open files — nothing broader:

  • --socket=wayland, --socket=fallback-x11 — display access
  • --device=dri — GPU access for the glow/wgpu renderer
  • --share=ipc — required alongside the display sockets

No --filesystem permission is granted. rfd (the file-dialog crate) pulls in zbus, not GTK — on Linux it talks to the org.freedesktop.portal.FileChooser portal, which grants access to whatever the user picks in the dialog without the sandbox needing broad filesystem access up front.

Known limitation: not Flathub-ready

The manifest builds with --share=network and lets cargo build --release fetch dependencies from crates.io live, inside the sandbox, on every clean build. That's fine for local use but is exactly what Flathub's review process rejects — submissions must build with network access disabled, which means vendoring every crate as a manifest source (typically generated from Cargo.lock via flatpak-cargo-generator into a generated-sources.json included as a module source). That step hasn't been done here.
