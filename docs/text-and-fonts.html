Text & Fonts

Typography, font resolution, and the per-character rich text model.

Font tiers

TextFont has three tiers, all drawn from the exact same font files on both the canvas (egui) and PNG export/outline-conversion (ab_glyph, which never goes through egui's font registry). fonts::ab_glyph_bytes is the single place that maps any TextFont to raw bytes for the latter two, so it must stay in sync with whatever the canvas side resolves to.

TierSourceNotes
Proportional / Monospaceegui's own built-in default familiesUbuntu-Light / Hack-Regular from epaint_default_fonts. No setup needed.
Serif / Display / HandwritingBundled in assets/fonts/Google Fonts, OFL-licensed (Merriweather, Poppins, Caveat); registered as named egui FontFamilys once at startup via fonts::install_fonts.
System(String)An OS-installed font, by family nameDiscovered via fontdb (system_fonts.rs) on macOS/Linux, no system library dependency. A .sdesign file referencing a family that isn't installed on the current machine falls back to Proportional everywhere — canvas, export, outlines — rather than panicking.

Two System-font gotchas

  • egui::Context::add_font only takes effect "at the start of the next pass" — laying out text against a FontFamily::Name before egui has bound it panics. Always resolve through system_fonts::resolve_family(ctx, name) (or resolve_family_bold), never construct that FontFamily by hand.
  • TextFont is Clone but not Copy (it holds a String for System) — call sites need .clone() or a reference-based match.

Bold and italic

Bold is a real font-weight swap, not a paint-time trick — except for a whole uniformly-styled layer (runs empty), which still uses the old "draw the galley/glyphs twice, offset" fake, since egui 0.36's FontId has no weight field at all. Every one of the five built-in tiers therefore ships a bundled bold-weight file too (including Ubuntu-Bold.ttf/Hack-Bold.ttf, since epaint_default_fonts only ships their regular weight). System's bold face is looked up via fontdb's Weight::BOLD query and, same graceful-degradation precedent as a missing family, silently falls back to the regular face if the family has no distinct bold one.

Italic has no bundled/OS face lookup at all — it's always the faux-shear trick, for both uniform and rich text.

Rich text (model/text_runs.rs)

A Text layer's runs: Vec<TextRun> field is either empty (uniform style — every one of LayerKind::Text's scalar fields, plus Layer::style.fill, applies to all of content) or non-empty and spans the entire content, each TextRun { len: usize, style: RunStyle } covering len chars (not bytes — matches egui's CCursor indexing) at a given font/size/color/bold/italic/underline/strikethrough. Paragraph-level properties (alignment, resize, line/letter/paragraph spacing, transform, list) stay layer-level only, never per-run.

The three entry points

FunctionPurpose
splice(runs, change_start, chars_removed, chars_inserted, base)Keeps runs in sync with every content edit (typing/deleting/pasting), called after diffing the old and new buffer.
apply(content, runs, base, char_range, edit)The "make this selection bold" entry point — lazily materializes runs from empty if needed, splits at the range's boundaries, edits, then coalesces adjacent equal-style runs back together.
mixed_or(runs, char_range, field)None if a selection spans differing values for a property (drives the Inspector's "Mixed" dual-mode controls), Some(value) if uniform.

Every render/measure site branches on runs.is_empty()

The non-empty branch is always new code added alongside the untouched original, never a modification of it:

  • canvas.rs::draw_layer's Text arm and apply_text_auto_resize call text_layout::layout_paragraphs_rich instead of layout_paragraphs
  • export.rs::draw_text has a draw_text_rich sibling, with its own wrap_line_rich that walks character-by-character to look up the right run's face
  • text_outline.rs::convert_to_outlines has a convert_to_outlines_rich sibling

All three rich paths share text_layout::tagged_lines (run-boundary + transform + list-prefix tagging) so they can't silently disagree on where a run boundary falls.

In-place editing over rich content

The canvas's editing_text overlay, when runs is non-empty, swaps TextEdit::multiline's plain .font()/.text_color() for a custom .layouter() (text_layout::editor_layout_job) — a whole-buffer single-Galley sibling of layout_paragraphs_rich, deliberately skipping tagged_lines's transform/list-prefix cosmetics, since injecting characters that don't exist in the real buffer would desync egui's char-index cursor/selection from the actual content. Because egui uses that same returned Galley for both painting and all click/drag/keyboard selection, the Inspector just reads the resulting CCursorRange off CanvasWidget::text_edit_selection each frame — no custom hit-testing was written for this.

Not supported

  • Text-on-a-path
  • OpenType features
  • "Sticky" formatting for the next typed character after a collapsed cursor
  • Applying a saved Text Style to a layer with rich per-run formatting resets it to uniform — Text Styles remain a whole-layer/paragraph concept, not a per-run one
