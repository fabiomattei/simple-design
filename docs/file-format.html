File Format

The .sdesign document format: plain, pretty-printed JSON with no binary payload beyond base64-encoded image bytes.

A .sdesign file is exactly a serde-serialized model::Document (serde_json::to_string_pretty, written verbatim by io::save_to) — there's no separate schema, versioning header, or compression. Loading (io::load_from) just parses it back with serde_json::from_str. Every field added since the format's first version is annotated #[serde(default)] in the Rust structs, so older files always load — missing fields fall back to a value that reproduces the pre-existing behavior exactly (e.g. a missing opacity defaults to 1.0, a missing rotation defaults to 0.0).

Top-level shape

{
  "name": "Untitled",
  "pages": [ /* Page[] */ ],
  "active_page": 0,
  "text_styles": [ /* TextStyle[], shared/linked text styles */ ],
  "layer_styles": [ /* LayerStyle[], shared/linked fill+stroke+shadow styles */ ],
  "palette": { /* Palette — color-swatch library, see model/palette.rs */ }
}

text_styles, layer_styles, and palette were all added after the format's first version, so each is #[serde(default)] — files saved before they existed simply load with an empty style library and the default DawnBringer DB32 palette.

Page

{
  "id": "e3b0c442-...",
  "name": "Page 1",
  "layers": [ /* Layer[], top-level layers on this page */ ],
  "guides": [ /* Guide[], ruler guides — see model/guide.rs */ ]
}

Layer

Every layer — regardless of kind — shares the same envelope. frame.pos is relative to the parent (page, or enclosing Artboard/Group/BooleanGroup), not an absolute page coordinate; see Architecture for why. kind is a serde-tagged enum, so its own fields sit inline alongside the shared ones (internally tagged on a kind-shaped structure — the exact wire encoding depends on the specific LayerKind variant). 

{
  "id": "9c858901-...",
  "name": "Rectangle 1",
  "frame": { "pos": [40.0, 60.0], "size": [200.0, 120.0], "rotation": 0.0 },
  "style": {
    "fill": [216, 216, 216, 255],
    "stroke": { "paint": [30, 30, 30, 255], "width": 1.0 },
    "fill_opacity": 1.0,
    "stroke_opacity": 1.0
  },
  "visible": true,
  "locked": false,
  "opacity": 1.0,
  "is_mask": false,
  "ignore_mask": false,
  "bool_op": "Union",
  "kind": {
    "Rectangle": {
      "corner_radius": { "top_left": 0.0, "top_right": 0.0, "bottom_right": 0.0, "bottom_left": 0.0 }
    }
  }
}

Layer kinds

KindNotable fields
Artboardchildren: Layer[], background: Color32

Rectanglecorner_radius — independent per-corner
Oval, LineGeometry comes entirely from frame

Imageencoded: String (base64 PNG bytes), plus pixel width/height

Paint encoding (fill / stroke color)

style.fill and stroke.paint both hold a Paint, which is #[serde(untagged)] — serde tries each variant's shape in turn, so a plain solid color serializes as a bare [r, g, b, a] array rather than a wrapped object. This is deliberate: it's the exact shape those fields used before Paint existed, so every older .sdesign file still loads unchanged, with every solid color becoming Paint::Solid. 

"fill": [216, 216, 216, 255]                             // Solid

"fill": {                                                 // Gradient
  "kind": "Linear",
  "stops": [
    { "offset": 0.0, "color": [255, 0, 0, 255] },
    { "offset": 1.0, "color": [0, 0, 255, 255] }
  ],
  "from": [0.0, 0.0], "to": [1.0, 1.0]
}

"fill": { "base": [128,128,128,255], "intensity": 0.3,    // Noise
          "scale": 4.0, "seed": 1234 }

"fill": { "background": [255,255,255,255],                // Halftone
          "dot": [0,0,0,255], "scale": 8.0, "coverage": 0.6 }

"fill": { "encoded": "iVBORw0KG...", "tile_width": 64.0 } // Pattern (base64 PNG)

Gradient/Noise/Halftone/Pattern are fill-only in the UI (a stroke can only ever be Solid/Gradient) but the type itself doesn't enforce that — a hand-edited document with a textured stroke paint would still deserialize fine, just never be reachable from the Inspector.

Shared style libraries

text_styles and layer_styles (top-level, see above) hold named, reusable styles a layer links to by id rather than embeds: 

// TextStyle — Document.text_styles[i]
{
  "id": "b1a2...", "name": "Heading/H1",
  "font_size": 32.0, "font": "Proportional", "align": "Left",
  "vertical_align": "Top", "line_height": null, "letter_spacing": 0.0,
  "paragraph_spacing": 0.0, "bold": true, "italic": false,
  "underline": false, "strikethrough": false, "transform": "None",
  "list": "None", "list_start": 1, "fill": [20, 20, 20, 255]
}

// LayerStyle — Document.layer_styles[i]
{
  "id": "c3d4...", "name": "Card/Elevated",
  "fill": [255, 255, 255, 255],
  "stroke": { "paint": [220, 220, 220, 255], "width": 1.0 },
  "fill_opacity": 1.0, "stroke_opacity": 1.0,
  "shadows": [ { "color": [0,0,0,80], "offset": [0.0, 4.0], "blur": 8.0, "spread": 0.0 } ],
  "inner_shadows": []
}

A layer links to one via style_id (LayerKind::Text::style_id for a TextStyle, Layer::style_id for a LayerStyle) — applying one is a straight field copy onto the layer, so the layer's own fields stay independently editable afterward and only drift out of sync with the library entry until the next "Update Style"/re-apply. Editing a linked layer's fields directly does not clear style_id; only an explicit "Detach" does.

Round-trip guarantees

  • An Image layer's bytes survive a full save/load cycle through serde_json::to_string_pretty unmodified — covered by an automated test in io.rs.
  • A System(String) font referenced by a layer that isn't installed on the machine opening the file falls back to Proportional at load/render time — the document itself still stores the original family name, so it renders correctly again on a machine that has it.
  • Loading never panics on a missing newer field; every addition to the format is backward-compatible via #[serde(default)].

Exporting

PNG export (⌘E, or right-click in the Layers panel) is a one-way operation — it rasterizes a single selected layer and its children through the independent export.rs renderer (tiny-skia), and does not round-trip back into .sdesign.
